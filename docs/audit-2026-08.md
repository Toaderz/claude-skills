## 2. Zero machinery

Verified absent from the repository root:

```
.claude/          ABSENT      .claude-plugin/   ABSENT
.mcp.json         ABSENT      package.json      ABSENT
.gitignore        ABSENT      .github/          ABSENT
```

There are no hooks, no commands, no subagents, no plugin manifest, no marketplace manifest, and
no executable code of any kind. The repository is 29 markdown/text files plus one ZIP.

### Consequence: nothing in this repository auto-invokes

Claude Code discovers skills at `.claude/skills/<name>/SKILL.md` (project) or
`~/.claude/skills/<name>/SKILL.md` (user), or through an installed plugin. **None of these files
sit at a discoverable path.** They live at the repo root in directories whose names do not match
their declared `name:` fields:

| Directory | Declared `name:` | Match? |
|---|---|---|
| `Claude_optimization/` | `claude-optimization` | no |
| `Improve code/` | `improve-codebase-architecture` | no — **and the directory name contains a space** |
| `research/` | `news-prioritization` | no |
| `session-snapshot/` | `session-snapshot` | yes |
| `workflow-orchestrator/` | `workflow-orchestrator` | yes |
| `project-structure-governor/` | `project-structure-governor` | yes |
| `find-skills/` | `find-skills` | yes |
| `icm-architect/` | `icm-architect` | yes |

The only mechanism currently routing anything is `CLAUDE.md` instructing Claude to read specific
files by path. It names 3 of the 8 skill directories. The other 5 are unreachable by any
mechanism, automatic or manual.

`Improve code/` breaks tooling in practice, not just in principle: iterating the file list with
default word-splitting splits the path into `Improve` and `code/SKILL.md`, both of which fail to
open. This was observed while collecting the evidence for this audit.

## 3. Invalid skill name

`Claude_optimization/SKILL.md` declares:

```yaml
name: claude-optimization
```

Skill names may not contain the reserved words `anthropic` or `claude`. This name is invalid under
the current specification and would be rejected. The file is also only 18 lines and functions as a
pointer to its three sibling files — it carries no behaviour of its own.

## 11. Already native — must not be rebuilt

Available without adding anything to this repository:

`docx` · `pdf` · `pptx` · `xlsx` · `/code-review` · `/security-review` · `dataviz` ·
`artifact-design` · `skill-creator` · `WebSearch` · `WebFetch` · the `Agent` tool ·
official claude.ai connectors (including Gmail)

**Claude Code already routes skills.** At startup it preloads only each skill's `name` and
`description` and loads the body on match. A custom runtime router built on top of this would add
ambient token cost to duplicate a free mechanism. The correct levers are description quality,
installation scope, correct frontmatter, and `paths:` globs — in that order.

## 13. What this audit does not establish

- **No token count is authoritative.** The ~39,000 figure in §1 is a bytes/4 estimate. Real
  measurement requires `claude plugin details`, which needs a plugin manifest that does not
  exist yet.
- **No routing behaviour was measured.** Whether Claude activates a given skill for a given
  prompt requires a runtime evaluation, which incurs monetary cost and was not authorized. Every
  routing statement in this document is structural — about discoverability paths and frontmatter
  validity — not about semantic activation.
